# Git の5つの場所

Git 初心者向けの学習ページ。5つの場所（スタッシュ・作業フォルダ・ステージング・ローカルリポジトリ・リモートリポジトリ）を縦に並べ、コマンドを横の矢印で描く。

**デモ**: https://tsubasa37.github.io/git-visualizer/ （ブラウザでそのまま使える）

- **前提の設定**: 本流（master / main）、起点ブランチ（切る元でプルリクエストの行き先）、自分とほかの人のブランチ名を決められる。決めた名前が、早見表・パターン・ブランチの図・説明文のすべてに入る。設定はそのブラウザにだけ保存される
- **コマンド早見表**: 現場で毎日使うコマンド（17個）。矢印の下には、そのコマンドが何をするかを1行で出す。同じ結果になる書き方（switch と checkout、restore と checkout -- など）は行を分けず、クリックで開く説明にまとめる（場面によって結果が変わる書き方は、その条件と一緒に書く）。リモートにしか無いブランチは、名前だけの `git switch 名前` で持ってこられる（`-t origin/名前` でも同じ。`-b` / `-c` を付けるなら `origin/名前` まで書く）。コマンドをクリック（スマホはタップ）すると、どこからどこへ動くか・注意・よくある誤解の説明が開き、× で閉じるまで出たまま（広い画面では盤面の右の列に出て、盤面に重ならない）。ホバーは行を光らせるだけ
- **応用編**: ときどき使うコマンド（17個。rebase・reset・revert、コンフリクトしたときの取り込みなど）
- **パターンで学ぶ**: チーム開発の流れ4パターン（本流にはプルリクエストを画面でマージして入れ、手元へは pull で取り込む。手元で merge したり本流へ push したりはしない）。各手順に switch と checkout の両方の書き方を載せる。手順ごとに矢印とブランチの横線図が連動する

初期値は本流 `master`、作業ブランチ `feature/login-form`、ほかの人のブランチ `feature/profile-page`。

## 開き方

ビルド不要。`index.html` をブラウザで開く。

## テスト

```bash
bash scripts/verify-git.sh          # ページに書いた Git の挙動を使い捨てリポジトリで確かめる
node scripts/check-data.mjs         # データの食い違い・名前の直書き・チーム開発の前提（パターンで手元の merge をしない等）・同じ結果のコマンドの重複を調べる
node scripts/check-branch-names.mjs # ブランチ名の判定が git check-ref-format と一致するか
node scripts/check-public.mjs       # 公開前チェック（メールアドレス・PC のパス・公開しない言葉）
```

画面の動作は `scripts/browser-check.js` の中身を、ページを開いた状態で開発者ツールのコンソールに貼って実行する（名前の反映・入力チェック・図の重なり・保存と初期化・レイアウト）。最後に設定を初期値へ戻す。

公開前チェックの「公開しない言葉」は、リポジトリ直下の `.private-words`（1行に1つ）に書く。このファイルは `.gitignore` で Git に入らない。

説明文を直したら、対応する検証も直してから全部を通す。

## 1ファイルにまとめる

```bash
bash scripts/build-artifact.sh      # dist/git-visualizer.html に CSS・JS を埋め込んだ1ファイルを作る
```

## ファイル

| パス | 中身 |
|---|---|
| `js/data-commands.js` | 5つの場所の定義と、早見表・応用編のコマンド（名前は `{start}` `{mine}` などで書く） |
| `js/data-patterns.js` | パターンの手順と、コミットの図の状態 |
| `js/branch-names.js` | ブランチ名の判定と、説明文への差し込み（画面を使わない） |
| `js/settings.js` | 前提カードの入力欄と保存 |
| `js/board.js` | レーン盤面（矢印）の描画 |
| `js/app.js` | タブ・吹き出し・パターン・ブランチの図 |
| `css/style.css` | 見た目（ライト／ダーク両対応） |
