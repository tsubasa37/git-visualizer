Git の5つの場所

コマンドを打つと、何が・どこから・どこへ動くのか。5つの場所を縦に並べ、コマンドを横の矢印で描きました。コマンドをクリック（スマホはタップ）すると、何が起きるかの説明が出ます。

この例の前提（名前は自分の現場に合わせて変えられます）

リモートの名前
origin（clone 元のサーバー。GitHub・GitLab など）
起点ブランチ
作業ブランチを切る元で、プルリクエストの行き先。ふつうは本流と同じです
ほかの人のブランチ
手元に持ってきて、続きを作業するブランチの例です
Git のバージョン
Git 2.23 以降が前提です（switch と restore は 2.23 からあります）。それより古い Git では、「または」にある checkout や reset の書き方を使います
master と main の違い どちらも「本流」のブランチの名前で、役割は同じです。GitHub や GitLab で新しく作るリポジトリは main が既定になりましたが、昔からのプロジェクトは master のことが多いです。1つのリポジトリにあるのは、ふつうどちらか一方です。 いまの設定：本流は {base}、ブランチを切る起点（プルリクエストの行き先）は {start}、あなたのブランチは {mine} です。
いまいるブランチ{mine}早見表の例は、このブランチにいる前提です。コマンドをクリックすると説明が出ます（× で閉じるまで出たままです）。
いまいるブランチ{mine}コマンドをクリックすると説明が出ます。早見表のコマンドに慣れてから使うものです。取り消し系は、使う前に git status で状態を確かめてください。

用語ミニ辞典

HEAD
いまいるブランチを指す目印。図では「HEAD → ブランチ名」の札で表しています。
origin/{start}（写し）
最後に fetch した時点で、リモートの {start} がどこにあったかを覚えている札。正式にはリモート追跡ブランチといい、fetch・pull・push のときだけ動きます。
追跡先（upstream）
引数なしの git push・git pull が相手にするリモートのブランチ。git push -u のほか、リモートのブランチから作る git switch -c 名前 origin/名前 でも設定されます。
fast-forward
分かれ道が無いので、札を先へ進めるだけで取り込めること。マージコミットはできません。
プルリクエスト（PR）
「このブランチを {start} に入れてください」と頼む仕組み。GitHub ではプルリクエスト、GitLab ではマージリクエスト（MR）と呼びます。

よくある誤解

  • git pull はリモートから作業フォルダに直接届く → 写し origin/… を更新してから、いまいるブランチに merge する2段階です。
  • git pull origin {start} で {start} に移る → 移りません。{start} の変更が、いまいるブランチに入ります。手元の {start} も古いままです。
  • ブランチを作るとファイルがコピーされる → 札が1枚増えるだけです。git switch -c（git checkout -b）ではファイルは変わりません。
  • コミットは永久保存 → push 前なら作り直せます。push 後の取り消しは revert で。
  • リモートは自動で同期されるクラウドドライブ → push したコミットだけが送られます。コミットしていない変更は送られません。

ページ内の挙動は Git 2.54 で実際に動かして確かめています（scripts/verify-git.sh）。表示される文面は、Git のバージョンによって少し違うことがあります。GitHub・GitLab の画面操作（プルリクエストの作成・マージ）は、リポジトリの設定によって違うことがあります。
